# Apploader reconstruction

Use C for target sources and the host converter. Build orchestration follows
upstream dtk-template's Python conventions. Apply `.clang-format`, matching Prime's
two-space indentation, 100-column limit and pointer alignment. Use traditional
`_HEADERNAME` guards, descriptive names, and natural source expressions.

Keep loader and reboot trailer configurations independent and versioned. Add
new versions without assuming their addresses, section boundaries, SDK revision,
compiler, flags or build timestamp match the initial image.

Commit split definitions before starting source matching/linking. Mark a source
object matching only after its instructions, data and relocations agree and it
links without changing the full image. Record conversion, original-object relink,
and source matching separately. Do not count preserved original objects as C
matches. Never patch generated bytes or emit executable byte arrays to claim a
match. Stock SDK low-level assembly extensions are distinct from C loader logic.

Reuse stock SDK sources with provenance. Keep dependencies external, rather than
copying unrelated repositories into this project. Exclude original images,
compiler binaries, generated ELFs/objects and local machine paths from commits.

The user has authorized the initial repository replacement and subsequent normal
commits to PrimeDecomp/gc-apploader through the GitHub MCP. Keep subsequent updates
fast-forward and check the remote head before publishing.
